# WKC

**WKC（Working Counter，工作计数器）** 位于每条 EtherCAT Datagram 的末尾，占 2 B。符合地址和访问条件的从站成功处理访问时，按命令规则增加它。主站将返回值与预期值比较，判断这次访问的参与情况是否符合配置。

## 它不是单纯的设备数量

一条命令可能只访问一台从站，也可能通过广播或逻辑寻址让多台从站参与。不同命令中，读、写的计数贡献还可能不同。

| 情形 | 典型计数贡献 |
| --- | --- |
| 单独的读命令，如 FPRD、LRD | 一次符合规则的成功读处理加 1 |
| 单独的写命令，如 FPWR、LWR | 一次符合规则的成功写处理加 1 |
| LRW 的读处理 | 加 1 |
| LRW 的写处理 | 加 2 |
| 同一从站对 LRW 同时成功参与读、写 | 合计加 3 |

例如三个从站各自参与一次 LRD 读访问，预期 WKC 可以是 3；两个从站各自在 LRW 中同时参与读和写，预期 WKC 可以是 6。因此，WKC 可以大于站数，也可以大于 3。

预期值应由实际命令、映射和参与方向确定，不能统一套用“每台加一”。计数也不按每个数据字节递增。

## 主站怎样使用

主站通常将发出 Datagram 的 WKC 初始化为 0，返回后检查：

```text
Actual WKC == Expected WKC
```

Expected WKC 由主站根据当前配置确定，而不是由网络返回一个“正确答案”。返回值不符，可能涉及从站掉线、地址错误、FMMU 未激活、访问方向不匹配或 SM 访问条件不满足。

WKC 能指出这一条 Datagram 的访问参与异常，但通常不能仅凭一个数字定位是哪台从站、哪一位数据出错；还需结合拓扑、逐站访问和状态诊断。

广播读取各站均支持的寄存器时，每站贡献一个成功读计数，可以据此统计参与从站数量。这是特定命令下的用途，见[寻址与命令](../../通信机制/寻址与命令/寻址与命令.md)。

## WKC 正常证明到哪一层

`FPWR → 从站邮箱` 返回 WKC=1，说明底层写访问得到处理，但从站应用可能随后发现对象不存在或参数不允许修改。SDO 是否成功仍需检查对应 SDO Response 或 Abort。

同样，过程数据 WKC 正常不证明电机已经使能、目标已经执行或反馈已经达到目标。它检查 EtherCAT 访问，应用行为由设备状态和控制逻辑决定。

WKC 也不能代替帧校验、[AL 状态](../../配置与运行/AL状态机/AL状态机.md)、[看门狗](../看门狗/看门狗.md)或 DC 误差检查。这些机制分别观察通信和应用的不同方面。
