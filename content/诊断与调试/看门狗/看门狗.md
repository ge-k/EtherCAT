# 看门狗

通信中的最后一份数据可以一直留在 RAM 里，但它可能已经过时。看门狗通过检查规定活动是否持续发生，发现“数据或访问停止更新”的问题。

## 过程数据看门狗

Process Data Watchdog 关注主站是否持续完成符合配置条件的过程数据输出访问。例如主站每 1 ms 更新目标转矩，突然断线后，最后一个目标值仍可能保存在 ESC 中。

```text
满足配置条件的过程输出写访问持续发生
→ 看门狗重新计时

超过设定时间没有相应访问
→ 看门狗超时
→ 报告状态，由设备按设计执行保护行为
```

它不是监视“网线上是否有任意报文”。持续读取状态、发送邮箱数据或更新其他未关联通道，不一定能喂这个看门狗；重触发条件与相关 SM 配置有关。

超时如何影响实际 IO 或电机，由 ESC 的支持能力、从站程序和设备安全输出策略共同决定。不能假定所有设备都由 ESC 自动完成同一种停机动作。

## PDI 看门狗

PDI Watchdog 关注本地 MCU 是否持续通过 PDI 访问 ESC。长时间没有符合规定的 PDI 活动，可能意味着 MCU 卡死、接口故障或任务没有运行。

它与过程数据看门狗的观察侧不同：

| 机制 | 主要监视方向 |
| --- | --- |
| 过程数据看门狗 | EtherCAT 网络侧的规定过程输出访问 |
| PDI 看门狗 | 本地应用侧的规定 PDI 访问 |

PDI 访问仍在持续，也不证明控制算法逻辑正确；看门狗能检查规定活动，却不能理解应用计算结果。

## 配置与排查

ESC 看门狗相关寄存器位于 `0x0400` 附近。配置时应使超时阈值与总线周期、任务调度和允许的异常窗口相匹配，并确认相关 SM 是否启用看门狗触发。

排查时区分主站漏发、报文未成功写入、SM 条件不符、本地 PDI 停止访问和应用自身故障。配合 [WKC](../WKC/WKC.md) 与 [AL 状态](../../配置与运行/AL状态机/AL状态机.md)，才能确定数据在哪一段停止更新。
