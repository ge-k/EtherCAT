# 事件与中断

事件表示 ESC 中发生了需要关注的变化，中断表示硬件选择用信号线通知 MCU。事件可以发生而没有产生 MCU 中断，因为通知还受使能、屏蔽和路由配置控制。

## 从 SM 事件到 MCU

例如主站完成一次受 SM 管理的过程数据写入，可以形成以下通知路径：

```text
SM 数据交接事件
→ AL Event Request 中相应事件状态
→ AL Event Mask 等配置允许通知
→ PDI IRQ
→ MCU 的中断输入与处理程序
```

三缓冲没有邮箱那样的 Buffer Full 握手，并不意味着没有数据完成事件。缓冲如何交换见 [SyncManager](../../通信机制/SyncManager/SyncManager.md)。

MCU 也可以轮询事件状态，不一定要使用 IRQ。进入中断后，程序还需读取和处理相应来源，按该事件规定的访问或确认动作消除请求；不能假定所有事件都通过“写 1 清零”处理。

## 常见事件来源

事件可来自 AL Control 改变、数据链路状态变化、SM 激活或数据交接、SYNC0/SYNC1、Latch 等。事件是否具备相应路由以及怎样确认，要结合 ESC 实现和配置。

ET1100 中常见的相关区域包括：

| 地址 | 功能 |
| --- | --- |
| `0x0200` | ECAT Event Mask |
| `0x0204` | AL Event Mask |
| `0x0210` | ECAT Event Request |
| `0x0220` | AL Event Request |

ECAT 事件面向 EtherCAT 侧的通知，AL 事件面向本地应用的处理；二者不是同一个寄存器的两种叫法。

## Datagram 的 IRQ 字段

EtherCAT Datagram 头里的 16 位 IRQ 字段可以合并沿途从站的 ECAT 事件请求。主站看到汇总后，可能还需要逐站读取状态确定来源。

这个字段不是从站拉给 MCU 的物理 IRQ 引脚，也不能直接当作完整 AL Event Request。前者随网络报文传递，后者属于 ESC 本地应用通知路径。

## 没进中断时怎样判断

先检查事件是否实际发生，再检查对应 SM/功能事件使能、AL Event Mask、PDI IRQ 配置，以及 MCU 引脚和中断控制器。还要确认程序是否已经通过轮询读取或其他访问处理了事件。

“收到了 EtherCAT 帧”“数据已经交接”和“MCU 进入了中断”是相关但不同的观察结果，需要分别定位。
