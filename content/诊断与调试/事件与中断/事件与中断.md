# 事件与中断

事件表示 ESC 中发生了需要关注的变化，中断是用信号通知处理方的一种方式。事件发生、请求位有效、MCU进入中断，是三个不同观察点。

## 两条通知路径

| 面向谁 | 请求寄存器 | 屏蔽寄存器 | 通知出口 |
| --- | --- | --- | --- |
| EtherCAT主站 | `0x0210～0x0211` ECAT Event Request | `0x0200～0x0201` ECAT Event Mask | 后续经过的Datagram的16位IRQ字段 |
| 本地MCU | `0x0220～0x0223` AL Event Request | `0x0204～0x0207` PDI AL Event Mask | 本地PDI IRQ信号 |

两种 Mask 均为1允许对应事件映射、0禁止映射。关闭Mask不等于事件没有发生。某些事件在进入请求寄存器前，还受 SM Control 或 SYNC映射配置限制。

```text
ECAT侧：事件 → ECAT请求位 → Mask允许 → 与经过的Datagram IRQ按位OR
                                              → 返回主站 → 逐站查来源

PDI侧：事件 → AL请求位 → Mask允许 → PDI IRQ → MCU中断输入和控制器
                                              → 中断处理函数检查来源
```

ESC不会因为发生ECAT事件就自行发一帧给主站；需要有主站报文经过并把IRQ带回。IRQ字段是沿途汇总，不能直接给出哪台从站产生事件。

MCU也可以轮询AL Event或相关状态，事件被轮询处理后，可能已没有待响应的中断。不能由抓包中的IRQ=0推断MCU没有PDI或SYNC0中断。

## ECAT Event 的常见位

以下以 ET1100 为例，按寄存器整体编号：

| 位 | 来源 | 典型确认/清除动作 |
| --- | --- | --- |
| bit0 | DC Latch | 对ECAT控制的Latch单元，由ECAT读取相应锁存时间，直到无待处理事件 |
| bit2 | DL Status变化 | ECAT读取`0x0110～0x0111` |
| bit3 | AL Status变化 | ECAT读取`0x0130～0x0131` |
| bit4～11 | SM0～SM7面向ECAT侧的事件 | 按SM交接方向访问缓冲 |

bit1及bit12～15保留。Mask配置不会替代这些确认动作。

## AL Event 的常见位

| 位 | 来源 | 正常读确认方式下的处理 |
| --- | --- | --- |
| bit0 | AL Control被写入 | PDI读取`0x0120～0x0121` |
| bit1 | PDI控制的DC Latch事件 | PDI读取相应锁存时间，直到无待处理事件 |
| bit2、3 | 映射的SYNC0/1状态 | Acknowledge模式下PDI读`0x098E/0x098F`确认 |
| bit4 | 至少一个SM Activate变化 | PDI读取所有发生变化的Activate寄存器，例如`0x0806、0x080E` |
| bit8～15 | ET1100的SM0～SM7数据交接事件 | 按SM的Write/Read Event规则访问缓冲 |

SYNC映射还需 `0x0151.bit3/bit7` 允许，并应在Acknowledge模式使用，详见[SYNC 与 Latch](../../时钟同步/SYNC与Latch/SYNC与Latch.md)。启用了特殊PDI写确认方式的实现，确认动作须按对应定义调整。

通用ESC寄存器布局还定义bit5为EEPROM仿真命令、bit6为过程数据看门狗事件，以及bit16～23对应更多SM。这些功能**不能全部套给ET1100**：ET1100的bit5/6保留，只有8个SM。对支持bit6的ESC，PDI读取`0x0440`可确认该事件，但读取状态不是喂狗。

## 用SM2输出交接串起各层

假设正常启用的SM2为ECAT写、PDI读：

1. 主站成功完成SM2缓冲写入，SM2 Status.bit0（Write Event）置1。
2. SM2 Control.bit5允许时，事件到AL Event.bit10；AL Event Mask.bit10允许且本地中断通路有效时，MCU收到PDI IRQ。
3. MCU读SM2首字节，Write Event清除；随后仍须完成有效数据读取和缓冲收尾。
4. 完成读访问后，SM2 Status.bit1（Read Event）置1。
5. SM2 Control.bit4允许时，事件到ECAT Event.bit6；ECAT Event Mask.bit6允许时，后续报文IRQ带回该事件。
6. 主站开始下一次写访问、写入首字节后，Read Event清除。

通知读方的是写完成，通知写方的是读完成。邮箱应答SM的方向相反，但规则相同。相关寄存器与特殊长度限制见[SM寄存器与访问规则](../../通信机制/SyncManager/寄存器与访问规则/寄存器与访问规则.md)。

## 没进中断时怎样排查

先核对是否存在实际触发源和有效访问，再查功能使能、请求位、Mask、PDI输出配置、引脚连接和MCU中断控制器。最后确认软件是否已轮询清除、是否正确识别事件来源。

硬件适配层调用的 `PDI_Isr()` 是具体固件接口，不能把任何一次PDI IRQ都当成新的RxPDO。状态机、邮箱和过程数据也不必全部采用中断，固件可以按功能选择轮询与中断。
