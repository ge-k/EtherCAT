# 端口与回环

ET1100 最多有 Port 0～3，每个通信端口具有收发方向。
ESC 内部按规定路径转发，链路末端或关闭端口 通过 内部回环 使帧走返回路径。

以从 Port 0 进入的 ET1100 路径为例，
可按 `Port 0 → EPU → Port 3 → Port 1 → Port 2 → Port 0` 理解端口处理次序，
某个端口的外部支路会先被 遍历并返回，再继续后续端口。

线型网络：
不需要额外拉一根从末端回到主站的网线，也可以形成帧的逻辑返回路径。
树形网络：
一条支路遍历完成后再继续另一条支路，实际访问次序由端口连接和内部转发顺序决定。

这个次序关系到启动时按位置找从站，也关系到[DC 时钟](../../时钟同步/DC时钟/DC时钟.md)的传播延迟测量。


## Port 0 为什么应朝向主站

正常拓扑中 ET1100 的 Port0 是上游，Port1～3 是下游；故障冗余运行是另有规则的情形。每个端口本身都能收发，IN/OUT 表示拓扑角色，不是网线只单向传输。

若中间站 B 反接：`A.Port1—B.Port1，B.Port0—C.Port0`，报文可能仍能经过整个网络，但 EPU处理顺序变成 A、C、B。因此能扫描到或能进入 OP，不足以证明端口朝向正确。

## 自动回环怎样阻止旧帧无限循环

断线后，原本已在下游的帧可能被两个回环端点困住。如果旧帧持续包含符合触发条件的输出写访问，就可能不断刷新[过程数据看门狗](../../诊断与调试/看门狗/看门狗.md)，即使主站已无法更新输出。

ET1100 在 **Port0 环路关闭，且控制模式为 Auto 或 Auto close** 时，由 EPU 检查 Datagram 的 C（Circulating）位：

| 原C值 | 处理 |
| --- | --- |
| 0 | 置1，继续处理和传递 |
| 1 | 不再处理，销毁帧 |

Port0正常打开时，不因经过该站就把 C置1，也不单凭 C=1丢帧。销毁后可能仍有片段在链路上流动、引发活动灯，但它不能继续作为有效输出帧处理。

正常连接 `A.Port1—B.Port0，B.Port1—C.Port0`，A与B之间断线后，下游孤立部分有 B.Port0 自动关闭，旧帧再次经过时能够被上述规则清除。

如果 B反接为 `A.Port1—B.Port1，B.Port0—C.Port0`，A与B之间断线后，下游孤立部分两端的回环落在 B.Port1和C.Port1，可能绕开依赖 Port0 自动关闭的检测。这个例子说明为什么不能把任意网口都当作上游口。

## 怎样检查端口是否接反

先读 DL Status `0x0110～0x0111`：bit4～7为各端口物理Link；bit8、10、12、14为Loop状态，1表示关闭；bit9、11、13、15表示相应端口通信建立状态。单看两端口都Link up，不能区分中间站哪一侧朝向主站。

可再用 BWR写`0x0900`触发同一测量帧的接收时间锁存，随后读取有效端口时间并结合拓扑。在同一颗 ESC 中，若有效 Port1接收时间早于Port0，说明该帧先从Port1到达，应结合回环状态检查上游接线。比较前须处理32位时间回绕，并排除未连接端口的无效或旧时间。

比较同一颗 ESC 的端口时间不需要先同步不同从站的时钟。只有一个端口连接的末端，通常也可直接用 Link位辅助检查朝向。测量过程见[DC 时钟](../../时钟同步/DC时钟/DC时钟.md)。

## 自动与强制环路控制

DL Control `0x0100～0x0103` 中，bit9:8、11:10、13:12、15:14分别控制Port0～3：

| 值 | 模式 |
| --- | --- |
| `00` | Auto：链路断开自动关闭，恢复后自动打开 |
| `01` | Auto close：链路断开自动关闭；恢复后按重新写入控制或收到有效帧等规定条件打开 |
| `10` | 强制打开 |
| `11` | 强制关闭 |

强制关闭不能直接等同于满足循环帧防护的自动关闭条件。拓扑配置应遵循芯片和主站要求。
