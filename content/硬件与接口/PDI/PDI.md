# PDI

**PDI（Process Data Interface，过程数据接口）** 是从站本地应用访问 ESC 的接口。EtherCAT 主站通过网络访问 ESC，MCU 则通过 PDI 访问 ESC，两者从不同侧操作同一套控制和数据资源。

```text
主站 ── EtherCAT ── ESC ── PDI ── MCU / 本地 IO
```

## ET1100 的接口选择

| PDI 形式 | 使用方式 |
| --- | --- |
| 数字 IO | 直接连接输入输出信号，简单应用可以不使用 MCU；ET1100 支持最多 32 位数字 IO |
| SPI | MCU 通过串行接口读写 ESC，使用较少连接线 |
| 并行微控制器接口 | MCU 通过地址线、数据线和控制信号访问 ESC，ET1100 支持 8/16 位及同步/异步形式 |

这些是不同的 PDI 模式，并非同一组复用引脚可以同时承担所有功能。接口模式及引脚含义需要一致配置。

## 并行接口怎样访问地址

地址总线指出本次访问的 ESC 寄存器或 RAM 地址，数据总线传输实际内容。例如 MCU 读取保存目标位置的 RAM 时，发出的地址是 ESC 内部地址，而不是主站使用的 32 位逻辑地址。

16 位访问还需要表达访问低字节、高字节或整个字。低有效的 `BHE` 表示高字节使能；8 位接口不使用高 8 位数据线。

ET1100 异步接口通过 BUSY 等握手信号反映访问等待，同步接口使用 TA 等应答信号。MCU 不能只按自己的速度连续访问，必须满足所选接口规定的等待和结束时序。

## SPI 与通知信号

SPI 通过片选、时钟和串行数据线完成访问。ESC 还可用 IRQ 通知 MCU 处理事件，但 IRQ 是通知路径，实际数据仍需通过 PDI 读取。

事件存在并不必然产生中断，还要满足使能和屏蔽条件，见[事件与中断](../../诊断与调试/事件与中断/事件与中断.md)。

## 上电时先确定接口

ET1100 的 PDI Control 位于 `0x0140`，ESC Configuration 位于 `0x0141`；PDI 模式相关选项还涉及 `0x0150` 起的配置区域。接口选择、ESC 功能控制和某个 PDI 的具体时序选项应分别理解。

这些初始设置来自 SII 的启动配置区。只有在电源、时钟、复位和配置加载满足要求、PDI 已具备工作条件后，MCU 才能正常访问。配置区和运行期参数的关系见[设备描述](../../配置与运行/设备描述/设备描述.md)。

PDI 解决“MCU 怎样访问”，并不自动保证一整批数据的读写一致性。网络侧和 MCU 侧交换过程数据时，还需要遵守[SyncManager](../../通信机制/SyncManager/SyncManager.md)的访问规则。
