# MDIO

PHY 负责线路信号，但也有速率、双工、自协商、链路状态等配置和状态寄存器。**MDIO（Management Data Input/Output）** 用来访问这些寄存器，也常称 MIIM 或 SMI；厂商使用 SMI 这个名字时还要确认具体协议。

先区分两条通路：

```text
MAC/ESC ←→ MII 数据通路 ←→ PHY ←→ 网线
管理控制器 ←→ MDC/MDIO ←→ PHY 内部寄存器
```

MII 承担帧数据，MDIO 承担管理访问。管理控制器可以位于 MAC、ESC 或 MCU 中，不必是 CPU 内部的 MAC。它既能在启动时配置 PHY，也能在运行时查询状态；是否允许运行中修改某项配置取决于器件要求。物理数据链路见[物理连接](../物理连接/物理连接.md)。

## 两条信号线

| 信号 | 方向与作用 |
| --- | --- |
| MDC | 管理控制器输出时钟，PHY接收 |
| MDIO | 双向数据，双方按管理帧规定交接驱动权 |

这是同步、串行、半双工接口。接收方按规定在 MDC 上升沿采样，字段先传最高位。传统 Clause 22 时序的 MDC 周期至少400 ns，即最高2.5 MHz，高、低电平各至少160 ns；更高频率须同时满足控制器、PHY和板级时序规格。

MDIO 空闲或换向时需要高阻释放，外部上拉维持高电平。不要把这一要求写成所有器件的输出电路都固定是开漏；应核对双方电气实现、上拉值、电容及电压兼容性。不能通用地通过“MAC内部下拉”判断 PHY 是否存在，应读取标识/状态并检查有效应答。

多个 PHY 可以共享 MDC/MDIO，但同一管理总线上的 PHY 地址应按硬件配置区分。

## Clause 22 的地址与寄存器

Clause 22 用5位 PHY 地址选择设备，再用5位寄存器地址选择一个16位寄存器，共32个可直接寻址的寄存器位置。它不表示某颗 PHY 内部总共只有32个寄存器；厂商分页和扩展访问可以提供更多内容。

| 地址 | 名称或用途 |
| --- | --- |
| 0 | Control：复位、速率、双工、自协商等控制 |
| 1 | Status：能力和链路等状态 |
| 2、3 | PHY Identifier |
| 4、5 | 自协商能力通告、链路伙伴能力 |
| 6～8 | 自协商扩展及 Next Page 相关信息 |
| 9、10 | 适用千兆铜缆 PHY 的主从配置与状态 |
| 11、12 | 相应标准版本中的 PSE 控制与状态 |
| 13、14 | MMD 扩展访问控制与地址/数据 |
| 15 | Extended Status，适用接口的扩展能力 |
| 16～31 | 厂商专用区域 |

对传统 MII，0、1是基础寄存器；千兆接口还使用扩展状态。表中扩展项是否实现取决于接口、标准版本和芯片。Clause 45 定义了更大的管理地址组织和相应访问格式，不能用本页的 Clause 22 帧格式直接解析它。

## 管理帧与读写换向

| 字段 | 位数 | 读 | 写 |
| --- | --- | --- | --- |
| PRE | 32 | 连续1 | 连续1 |
| ST | 2 | `01` | `01` |
| OP | 2 | `10` | `01` |
| PHYAD | 5 | PHY地址 | PHY地址 |
| REGAD | 5 | 寄存器地址 | 寄存器地址 |
| TA | 2 | `Z0` | `10` |
| DATA | 16 | PHY提供 | 管理控制器提供 |
| IDLE | — | 释放MDIO | 释放MDIO |

写操作从请求头到数据都由管理控制器发送，TA=`10`。读操作的请求头仍由管理控制器发送；到了 TA 第一位双方释放线路，第二位由目标 PHY 拉低，然后 PHY 发送16位数据。`Z`表示高阻，不是一个普通数据位。

只有相关器件支持并满足前导码抑制条件时，才能省略或缩短 PRE。下面两张笔记时序图从 ST 开始画，未画出32位前导码；图中 STA 是管理控制器。

## EtherCAT 主站怎样通过 ESC 访问 PHY

ET1100 提供下列 MII Management 命令接口：

| ESC 地址 | 用途 |
| --- | --- |
| `0x0510～0x0511` | 控制/状态：命令、写使能、Busy和适用错误位 |
| `0x0512` | 目标 PHY 选择，实际地址还要结合芯片的地址偏移规则 |
| `0x0513` | PHY寄存器编号0～31 |
| `0x0514～0x0515` | 16位读写数据 |

主站先确认 Busy=0，设置 PHY 和寄存器地址，写操作还要准备数据；随后发命令，等待 Busy结束并检查错误，读操作再取数据。

`0x0510` 的16位命令字段 bit9:8：`01`为读，`10`为写；这是 ESC 寄存器的命令编码，与线上 Clause 22 的 OP 编码不同。ECAT写操作需要在同一帧中设置 bit0 写使能并发写命令。

ET1100 的 PDI 控制该接口有 Transparent Mode 限制；通用 ESC 文档里的 `0x0516/0x0517` 控制权寄存器在 ET1100 上未实现，不能照搬某些 IP Core 的接管流程。
