# 网络分层

Ethernet、IP、TCP 和 EtherCAT 解决不同层次的问题。
理解它们的关系，可以避免把物理网口、TCP 端口和 EtherCAT 从站地址混为一谈。

## 普通网络通信怎样分层

以通过以太网传输的 Modbus TCP 为例：

```text
Modbus 请求或响应        应用层：数据表示什么操作
TCP                     传输层：连接、可靠传输、端口
IP                      网络层：IP 地址、跨网络传输
Ethernet                数据链路层：以太网帧、MAC 地址
PHY / 网线              物理层：信号怎样传输
```

| 名称 | 含义 | 例子 |
| --- | --- | --- |
| 物理网口 | 设备上的实际连接接口 | RJ45 插座、交换机第 1 口 |
| MAC 地址 | 以太网链路层地址 | `b8:3d:f6:36:c5:78` |
| IP 地址 | 配置在网络接口上的网络层地址 | `192.168.1.100` |
| TCP/UDP 端口号 | 传输层用于区分通信端点的编号 | Modbus TCP 服务通常使用 TCP 502 |

一个网络接口可以配置多个 IP。
TCP 和 UDP 各有自己的端口空间，TCP 5000 与 UDP 5000 不表示同一个传输端点。

在标准 Modbus TCP 请求—响应通信中，客户端发起请求，服务器返回响应。
设备是否能承担客户端或服务器角色取决于软件实现；
支持两种角色的设备可以同时服务其他客户端，并主动访问别的服务器。

## EtherCAT 怎样使用 Ethernet

常用的原生 EtherCAT 通信直接以 Ethernet 帧承载 EtherCAT 数据：

```text
Ethernet 帧
└─ EtherCAT 头
   └─ 一个或多个 EtherCAT Datagram
      └─ 寄存器、过程数据或邮箱数据
```

这条通信路径不需要 IP 地址、TCP/UDP 端口号。
Ethernet 头中的 **EtherType** 表明载荷采用什么协议，EtherCAT是`0x88A4` ，IPV4是`0x0800`。

EtherCAT 用 Datagram 内部的地址寻找设备或数据，
主要包括按位置、按配置站地址和按逻辑地址访问，见[寻址与命令](../../通信机制/寻址与命令/寻址与命令.md)。

## 同样使用网线，通信机制可以不同

普通应用通常由操作系统逐层处理 Ethernet、IP、TCP/UDP，再把应用数据交给程序。
EtherCAT 从站由 ESC 在帧经过时直接处理属于自己的数据，并继续转发。

因此，“都接在 RJ45 上”不意味着它们使用相同的软件协议栈。
PLC 的 EtherNET 口运行普通网络通信，而 EtherCAT 主站口运行 EtherCAT。

EtherCAT 的邮箱还可以承载 EoE，用于在 EtherCAT 网络内传输普通 Ethernet 帧，
见[邮箱与 CoE](../../通信机制/邮箱与CoE/邮箱与CoE.md)。
