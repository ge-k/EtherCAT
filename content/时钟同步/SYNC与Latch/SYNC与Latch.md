# SYNC 与 Latch

[DC 时钟](../DC时钟/DC时钟.md)让各站使用共同的时间基准。SYNC 与 Latch 把这个时间基准用于实际事件：SYNC 按时产生事件，Latch 在事件发生时记录时间。

## SYNC：时间到，产生事件

SYNC0/SYNC1 是 ESC 按配置的 DC 时间产生的同步事件或信号。主站配置启动时间、周期和相关相位，ESC 随后根据自己的已同步时钟产生事件，不必每次等待主站发来“现在执行”命令。

假设总线周期和 SYNC0 周期都是 1 ms，选定每个周期边界后 0.3 ms 为应用同步时刻：

```text
共同时间       通信与执行
0.0 ms 附近    传输本轮目标，各站先后收到
0.3 ms         约定的 SYNC0 时刻
1.0 ms 附近    传输下一轮目标
1.3 ms         下一次 SYNC0
```

这里的 0.3 ms 是共同时间表中的位置，不是每台从站在收到帧后分别等待 0.3 ms。后者仍会保留到达时间的先后差。

目标数据必须在设备要求的截止时间前到达并可用。DC 不能补救目标数据根本没有及时送到的问题。

## SYNC0 与 SYNC1 的配置

SYNC0 常作为基础周期事件，SYNC1 与 SYNC0 存在配置的相对时间关系。具体模式可能有不同调度方式，应把 SYNC1 理解为相关同步时序的一部分，不能无条件认为它始终是完全独立的第二个定时器。

| ET1100 寄存器地址 | 用途 |
| --- | --- |
| `0x0981` | 周期同步及相应信号激活控制 |
| `0x0982` | SYNC 信号脉宽 |
| `0x0990` 起 | 周期同步启动时间 |
| `0x09A0` | SYNC0 周期 |
| `0x09A4` | SYNC1 相对 SYNC0 的相关时序参数 |

脉宽、周期和启动时刻是三个不同量。EEPROM 预设了脉宽，不代表运行期同步时间表已经配置完成。

SYNC 事件如何通知 MCU、是否映射到外部引脚，以及应用在何时取数、运算或更新输出，取决于 ESC 与设备配置。不能只看到 SYNC0，就断定 MCU 中断和物理输出都在同一瞬间完成。

例如，固件可以先在 PDI 中断中取得目标并准备计算结果，再在 SYNC0 处理时采用；也可以在 SYNC0 处理时采样并计算。发布反馈到 ESC 与更新本地 PWM/IO 是不同动作，具体流程见[启动与周期运行](../../配置与运行/启动与周期运行/启动与周期运行.md)。

## 三种应用节拍

| 模式 | 决定处理时机的来源 | 主要特点 |
| --- | --- | --- |
| 自由运行 | 本地任务或定时器 | 与报文到达时间不直接绑定 |
| 数据事件同步 | 配置的 SM 读写事件 | 与数据交接关联，但各站到达时间存在先后 |
| DC 同步 | 共同时间表的 SYNC 事件 | 用统一时间安排采样或输出 |

SM 管理的是内存交接，SYNC 管理的是约定时刻，两者可以配合，但不能互相代替。

## Latch：事件到，记录时间

Latch 用于外部探针、光电信号或编码器索引等边沿的时间记录：

```text
外部边沿到达
→ ESC 硬件锁存 DC 时间
→ MCU 稍后读取时间戳
```

这样得到的是硬件检测到事件时的时间记录，而不是 MCU 经过中断延迟后才读取的软件时间。硬件输入与锁存仍有其精度和延迟指标，但避开了软件响应抖动这一主要因素。

ET1100 提供 Latch0/Latch1，可记录上升沿、下降沿，并支持单次或连续模式。单次模式适合保留一次事件供软件读取，连续模式则按配置持续更新；应用要根据读取速度选择模式，避免把后一次记录误当成前一次。
