# SYNC 与 Latch

[DC 时钟](../DC时钟/DC时钟.md)让各站，使用共同的时间基准。
SYNC 与 Latch 把这个时间基准，用于实际事件：
SYNC 按时产生事件，Latch 在事件发生时记录时间。

## SYNC：时间到，产生事件

SYNC0/SYNC1 是 ESC 按配置的 DC 时间，产生的同步事件或信号。
主站配置：启动时间、周期、相关相位，
ESC 随后根据自己的，已同步时钟，产生事件。

假设总线周期和 SYNC0 周期都是 1 ms，选定每个周期边界后 0.3 ms 为应用同步时刻：

```text
共同时间       通信与执行
0.0 ms 附近    传输本轮目标，各站先后收到
0.3 ms         约定的 SYNC0 时刻
1.0 ms 附近    传输下一轮目标
1.3 ms         下一次 SYNC0
```

这里的 0.3 ms 是共同时间表中的位置，不是每台从站在收到帧后分别等待 0.3 ms

## SYNC0 与 SYNC1 的配置

SYNC0 常作为基础周期事件，
SYNC1 与 SYNC0 存在配置的相对时间关系。

| ET1100 寄存器地址      | 用途                                                   |
| ----------------- | ---------------------------------------------------- |
| `0x0981`          | SYNC 输出单元激活、SYNC0、SYNC1脉冲生成                          |
| `0x0982`          | SYNC 信号脉宽                                            |
| `0x0990 ~ 0x0997` | 写：周期运行的起始系统时间，单位为 ns。<br>读：下一次 SYNC0 脉冲的系统时间，单位为 ns。 |
| `0x09A0`          | SYNC0 周期                                             |
| `0x09A4`          | SYNC1 相对 SYNC0 的相关时序参数                               |

EEPROM 预设脉宽。

SYNC 事件如何通知 MCU、是否映射到外部引脚，
应用在何时取数、运算或更新输出，取决于 ESC 与设备配置。

固件可以先在 PDI 中断，中取得目标，并准备计算结果，再在 SYNC0 处理时采用。
固件也可以在 SYNC0 处理时采样，并计算。
发布反馈到 ESC 与更新本地 PWM/IO 是不同动作，具体流程见[周期运行](../../配置与运行/启动与周期运行/周期运行/周期运行.md)。

## 周期、相位与激活的具体含义

`0x0980.bit0`选择周期单元由ECAT（0）还是PDI（1）控制；`0x0981`是独立的激活字节，bit0启用周期单元，bit1启用SYNC0，bit2启用SYNC1。写`0x0980`的两个字节`00 03`，表示ECAT控制、周期单元和SYNC0开启，SYNC1未开启。

先设置周期和未来的开始时间，再激活单元。ET1100不支持通用表中`0x0981.bit3`的“写Start Time自动激活”功能，应显式设置bit0。

例如开始时刻为1,010,000,000 ns，SYNC0周期为1,000,000 ns，SYNC1延迟为250,000 ns，则SYNC0每1 ms产生，SYNC1在对应SYNC0之后250 μs产生。

`0x09A0=0`表示SYNC0单次触发；`0x09A4=0`表示启用的SYNC1与SYNC0同相，不是“SYNC1只触发一次”。本例采用SYNC1延迟小于SYNC0周期的常见配置，更长延迟要按芯片规则解释。

两站开始时间可以不同而周期相位相同。例如3,762,600,000 ns和3,771,600,000 ns相差9个1 ms周期，对1 ms取余都为600,000 ns。它们后续落在相同的周期时刻序列上；实际边沿是否足够同步，还要结合DC误差和测量。

## 脉宽模式与PDI中断

ET1100的`0x0982～0x0983`以 **10 ns** 为单位，由SII初始化，不能把寄存器数值直接当成纳秒，也不能把它当作SYNC周期。

| 脉宽值 | SYNC信号行为 |
| --- | --- |
| 大于0 | 到点后输出固定宽度脉冲，随后自动恢复无效 |
| 等于0 | Acknowledge模式，保持有效直到PDI确认 |

“有效”可能是高电平也可能是低电平，由`0x0151`配置。bit1:0为SYNC0驱动/极性，bit5:4为SYNC1驱动/极性：`00`推挽低有效、`01`开漏低有效、`10`推挽高有效、`11`开源高有效。bit2/bit6分别选择对应引脚为SYNC输出或Latch输入。

SYNC0/1可以通过专用引脚通知MCU，也可以按`0x0151.bit3/bit7`映射到AL Event.bit2/bit3，再经过AL Event Mask进入PDI IRQ。寄存器手册要求这种AL事件确认路径用于Acknowledge模式；不能仅因设置映射位，就把固定宽度脉冲当作可靠保持的待处理事件。

普通PDI读确认方式下，读`0x098E`确认SYNC0，读`0x098F`确认SYNC1，清除相应挂起状态和映射事件。若实现启用了PDI写确认功能，应改按对应规则处理。ET1100没有`0x098C/0x098D`的SYNC2/3状态寄存器。

信号产生与MCU实际执行之间仍有中断延迟。SYNC0配置成功不证明MCU处理及时，也不保证主站操作系统发包毫无抖动。

## 三种应用节拍

| 模式     | 采样或输出的时机                 |
| ------ | ------------------------ |
| 自由运行   | 本地任务或定时器                 |
| 数据事件同步 | ESC 产生 SM 读写事件，触发 PDI 中断 |
| DC 同步  | 共同时间表 的 SYNC 事件          |

SM 管理的是内存交接，SYNC 管理的是约定时刻。

## Latch：事件到，记录时间

```text
外部边沿到达
→ ESC 硬件锁存 DC 时间
→ MCU 稍后读取时间戳
```

这样得到的是 硬件检测到事件时 的时间记录，而不是 MCU 经过中断延迟后才读取的软件时间。
硬件输入与锁存，仍有其精度和延迟指标，但避开了软件响应抖动这一主要因素。

ET1100 提供 Latch0/Latch1，
可记录上升沿、下降沿，并支持单次 或 连续模式。
单次模式适合 保留一次事件 供软件读取，连续模式则 按配置 持续更新；

## 记录SM访问时刻

除外部Latch输入外，ET1100还可按SM Activate中的Latch Event配置记录缓冲访问时刻：

| 地址 | 记录内容 |
| --- | --- |
| `0x09F0～0x09F3` | 引起ECAT侧缓冲交接事件的帧开始时的Local Time |
| `0x09F8～0x09FB` | PDI缓冲起始访问事件的Local Time |
| `0x09FC～0x09FF` | PDI缓冲交接事件的Local Time |

这些是共享的事件时间寄存器，不是每个SM各有一组。它们也不是外部LATCH引脚的边沿时间。事件来源、使能和单位必须结合[SM访问规则](../../通信机制/SyncManager/寄存器与访问规则/寄存器与访问规则.md)解释。

Latch单元的控制归属由`0x0980.bit4/bit5`选择，决定事件通知ECAT还是PDI。不能在双方都读取时忽略归属和清除条件。
