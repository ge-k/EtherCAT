# DC 时钟

**DC（Distributed Clocks，分布式时钟）** 使多个从站具有尽可能一致的时间基准。主站周期发送数据，并不意味着各站同时收到、同时处理；报文传播和本地任务安排都会造成先后差异。

DC 先对齐各 ESC 的时钟，再由应用选择共同的时间执行采样或输出。具体产生同步事件的方式见 [SYNC 与 Latch](../SYNC与Latch/SYNC与Latch.md)。

## 参考时钟与本地时钟

常见方案选择处理顺序中第一个支持 DC 的从站作为参考时钟。其他 DC 从站以其 System Time 为共同基准，主站负责配置和持续组织对时报文。

在这一模型中：

```text
本站 System Time = 本站 Local Time + System Time Offset
```

Local Time 是 ESC 内部运行的时间计数，Offset 用于对齐时间起点。时钟还存在走速误差，因此仅设置一次 Offset 不足以长期同步。

参考基准也不必等于主站 CPU 的时钟。主站任务仍需安排在合适时间窗口内，保证数据及时到达从站。

## 四个量分别解决什么

| 名称 | 含义 | 作用 |
| --- | --- | --- |
| Offset | 时钟起点偏移 | 对齐时间值 |
| Delay | 从参考位置到本站的传播延迟 | 区分线路耗时与时钟本身的误差 |
| Difference | 经过规定处理的当前同步误差 | 观察同步结果 |
| Drift | 时钟走速差造成的持续漂移 | 需要运行期持续补偿 |

例如参考时钟为 100000 ns，本地为 100350 ns，忽略传播影响时可通过约 -350 ns 的 Offset 对齐。若两块表之后每隔一段时间又多差 10 ns，则还有走速差。

固定差 10 ns 与差值从 10、20、30 ns 持续增长，是两种不同问题：前者存在时间偏差，后者还提示速率不一致。

## 主要寄存器

以下按 ET1100 的 64 位 DC 理解；其他 ESC 的实现位宽应按能力确认。

| 地址 | 长度 | 含义 |
| --- | --- | --- |
| `0x0900`、`0x0904`、`0x0908`、`0x090C` | 各 4 B | Port 0～3 Receive Time |
| `0x0910` | 8 B | System Time |
| `0x0918` | 8 B | EPU Receive Time |
| `0x0920` | 8 B | System Time Offset |
| `0x0928` | 4 B | System Time Delay |
| `0x092C` | 4 B | System Time Difference |
| `0x0930` | 2 B | Speed Counter Start，与控制环初始化有关 |
| `0x0932` | 2 B | Speed Counter Difference，与走速调节有关 |

System Time 持续变化。Port Receive Time 与 EPU Receive Time 是特定测量过程中锁存的时间快照，不是另几套不停增长的当前时间。

端口接收时间记录帧到达端口的时刻，EPU 接收时间记录帧到达处理单元的时刻，二者位置不同。锁存数据要与同一次测量以及正确的端口路径对应。

## 为什么先要知道拓扑

帧在树形网络中会遍历支路并返回。一个端口的两次相关经过之间，可能包含整条下游支路的耗时。因此，单独看到一个时间差，无法直接把它当成两站间线缆延迟。

主站先确定各站端口 Link/Loop 状态和转发路径，再触发接收时间锁存，读取各端口时间，结合拓扑计算 Delay。端口与回环的关系见[物理连接](../../硬件与接口/物理连接/物理连接.md)。

## 去程与回程的简化计算

考虑参考站 A 与后续站 B 都从 Port 0 进入、沿 Port 1 的下游支路返回的简化线型场景：

```text
去程：A 的 T1 ─────────→ B 的 T2 ───→ 下游
回程：A 的 T4 ←───────── B 的 T3 ←─── 下游
```

`T1、T4` 来自 A 的时钟，`T2、T3` 来自 B 的时钟。先在各自时钟内相减，可以消除固定的时钟起点差：

```text
单向传播延迟 d ≈ [(T4 - T1) - (T3 - T2)] / 2
```

这个式子依赖去回程近似对称、测量期间时钟走速近似一致、锁存点及内部延迟处理一致等条件。实际树形网络还需扣除相关支路并处理 ESC 内部路径，不能把所有相邻时间戳都直接代入除以二。

端口时间戳宽度有限，求差时还要考虑计数回卷。需要更稳定结果时，可以多次测量；拓扑稳定时传播延迟通常相对稳定。

## 初始配置与持续校准

主站通常执行以下工作：

1. 识别 DC 支持能力、时钟位宽和网络拓扑，选定参考时钟。
2. 触发统一的测量锁存，读取端口及所需 EPU 接收时间。倍福 ESC 的典型触发方式是 BWR 写 `0x0900` 的至少首字节。
3. 计算并写入 Delay、Offset，按 ESC 要求初始化同步控制环。
4. 周期分发参考时间，等待误差收敛并持续监测。

常用的分发命令为 `FRMW，ADO=0x0910`：参考站把当前 System Time 放进 Datagram，后续 DC 从站把它作为同步输入。

误差原理可以写成：

```text
e = 本站 System Time -（收到的参考 System Time + Delay）
e > 0：本站领先，适当放慢
e < 0：本站落后，适当加快
```

时间比较必须对应同一次同步访问的采样关系。这里的 e 是原理表达，不是把寄存器原始值直接强制转换成有符号整数的解码公式。

ESC 内部完成误差处理、滤波及本地数字时钟走速校正，`0x092C` 给出相应诊断结果。主站不需要每周期逐站发送“加速/减速”命令，也不是简单用收到的参考值直接覆盖本站时钟。

初始化期间即可开始控制环收敛，不必等待 OP。运行期间仍要分发参考时间，抵消晶振走速差。拓扑、链路和参考基准稳定时通常沿用 Delay/Offset；重连、复位或拓扑变化时则可能需要重新测量和配置。

## 怎样检查误差

BRD 读取 `0x092C` 得到各站数据的按位 OR 汇总，不是每台误差列表，也不是严格的最大误差。按寄存器有效位及相应阈值规则可以监视整体情况；要定位具体从站，应使用 FPRD 逐站读。

DC 时间同步合格只是应用同步的基础，数据仍需在约定执行时刻前准备好，见[启动与周期运行](../../配置与运行/启动与周期运行/启动与周期运行.md)。
