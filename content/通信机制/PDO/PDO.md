# PDO

**PDO（Process Data Object，过程数据对象）** 描述需要交换的过程数据，
例如伺服目标位置、实际位置、控制字、状态字和 IO 位。

## 方向从从站看

| 名称    | 从站视角 | 主站视角 | 例子       |
| ----- | ---- | ---- | -------- |
| RxPDO | 从站接收 | 主站输出 | 目标位置、控制字 |
| TxPDO | 从站发送 | 主站输入 | 实际位置、状态字 |

## 映射与分配

以支持 CoE 的设备为例，对象字典按 Index 和 SubIndex 标识参数。
PDO 分配，确定使用哪些 PDO。
PDO 映射，确定 哪些对象的哪些位 进入过程数据、按什么顺序排列、占多长。

常见分配对象 RxPDO `0x1C12`、TxPDO `0x1C13`
常见映射对象 RxPDO `0x1600` 起、TxPDO `0x1A00` 起。

主站可以通过 [SDO](../邮箱与CoE/邮箱与CoE.md) 修改设备允许配置的映射；默认映射已满足要求时可以直接沿用。

## 从分配列表追到数据对象

`0x1C12:00=1`表示RxPDO分配列表里有1项；`:01=0x1600`表示选用映射对象0x1600。它不表示只有一个输出点或一个字节。映射对象的`:00`则是该PDO内映射条目数。

每个常见32位映射条目由“对象索引16位、子索引8位、位长8位”组成：

| 映射值 | 数据对象 | 位长 |
| --- | --- | --- |
| `0x70000120` | `0x7000:01` | `0x20=32 bit` |
| `0x70000101` | `0x7000:01` | `1 bit` |

8项32 bit合计32 B，8项1 bit合计1 B；两台设备都叫0x1600或0x7000，不表示内部布局相同。输入方向可同样由0x1C13追到0x1A00，再追到输入数据对象。

映射条目保存“取哪个对象的几位”这一规则，数据对象才保存应用值。查询规则阶段还没有因此开始周期过程数据交换。

## 修改分配与修改映射不同

设备允许动态分配时，常在PRE-OP按以下顺序修改：先把分配对象`:00`写0，写`:01`等PDO索引，最后恢复`:00`的有效项数，并检查每次SDO应答。

例如`0x1C12:00=0 → :01=0x1600 → :00=1`只选择一个现有RxPDO；它没有重写0x1600内的条目。TxPDO分配可对0x1C13执行同类步骤。是否允许重映射、如何修改映射条目，仍受设备能力和访问权限约束。

## 对象字典与模块对象范围

对象字典是CoE沿用的CANopen数据与参数组织方式，SDO是访问它的一种服务。对象索引不同于ESC RAM地址。

采用相应模块化设备规范的设备，常按下表安排对象；不能无条件推广到所有EtherCAT设备：

| 对象范围 | 用途 |
| --- | --- |
| `0x6000～0x6FFF` | 模块输入数据 |
| `0x7000～0x7FFF` | 模块输出数据 |
| `0x8000～0x8FFF` | 模块配置参数 |
| `0x9000～0x9FFF` | 模块信息 |
| `0xA000～0xAFFF` | 模块诊断信息 |
| `0xF000`等 | 设备整体模块组织信息 |

参数对象存在，不等于主站每个周期都要用SDO访问它。运行时的主要数据路径由已经选定的PDO布局决定。

## 周期数据怎样到应用

```text
主站按 PDO 布局准备目标值
→ 通过 LWR/LRW 等过程数据访问发送
→ FMMU 将逻辑地址映射到从站 RAM
→ SM 管理网络侧和应用侧的数据交接
→ MCU 经 PDI 取得完整目标值
```

周期过程数据通常不重复携带每个对象的 Index/SubIndex，而按预先约定的偏移解释字节。
因此，主站与从站对映射的理解必须一致。

PDO 通道没有 SDO 那样逐次返回应用命令应答，但底层仍有 [WKC](../../诊断与调试/WKC/WKC.md)用于检查访问参与情况。

## PDO 与 SDO 的分工

SDO 采用请求—响应方式访问对象字典，常用于参数配置。
PDO 通道常用于周期性、实时交换。

数据传到 ESC、应用采用目标值、传感器采样反馈，是不同的时刻。
见[周期运行](../../配置与运行/启动与周期运行/周期运行/周期运行.md)。
