# 寄存器与访问规则

先理解[基本原理](../基本原理/基本原理.md)中的三缓冲和邮箱交接，再看寄存器。以下以 ET1100 为主；其他 ESC 可能增加状态位或支持不同的最小长度。

## 每个通道的八字节

SMn 的寄存器基址为 `0x0800 + 8 × n`，SM2 基址是 `0x0810`。

| 相对偏移 | SM2 地址 | 长度 | 含义 |
| --- | --- | --- | --- |
| +0 | `0x0810` | 2 B | DPRAM 访问窗口起点 |
| +2 | `0x0812` | 2 B | 一份缓冲的长度 |
| +4 | `0x0814` | 1 B | 模式、方向、事件与看门狗配置 |
| +5 | `0x0815` | 1 B | 缓冲与交接状态 |
| +6 | `0x0816` | 1 B | EtherCAT 侧激活、重复请求、时间锁存使能 |
| +7 | `0x0817` | 1 B | PDI 侧停用请求、重复确认 |

修改起点、长度或 Control 前，主站先清 Activate.bit0，配置完再置1。有效配置还必须满足芯片 RAM 范围、不重叠以及应用所需 PDO 长度等条件。

## Control：方向和通知分别设置

| 位 | 含义 |
| --- | --- |
| bit1:0 | `00`：三缓冲；`10`：邮箱单缓冲；其他值保留 |
| bit3:2 | `00`：ECAT 读、PDI 写；`01`：ECAT 写、PDI 读 |
| bit4 | 允许面向 EtherCAT 侧的交接事件 |
| bit5 | 允许面向 PDI/AL 侧的交接事件 |
| bit6 | 允许符合条件的写访问触发过程数据看门狗 |
| bit7 | ET1100 保留，写0 |

例如邮箱请求通道常用 `0x26`，邮箱应答通道常用 `0x22`；过程输出通道可用 `0x64`，过程输入通道可用 `0x60`。这些值来自具体配置组合，不是通道编号的固定属性。

输入通道即使 bit6=1，PDI 写输入或主站读输入也不因此成为主站过程输出写访问。触发条件见[看门狗](../../../诊断与调试/看门狗/看门狗.md)。

## 一次访问怎样开始和结束

正常 SM 缓冲访问从配置的起始地址开始；未先访问起点而直接访问中间数据会被拒绝。起点打开当前缓冲后，可一次或分次访问数据，最后访问末地址完成交接。不要在同一帧里重复访问同一缓冲末地址。

主站导致的缓冲切换还须通过帧检查，FCS 错误的帧不能发布一份成功的新缓冲。软件仍有责任写入或读取消息需要的全部有效数据，SM 不替应用检查内容是否正确。

邮箱长度与有效消息长度不同。例如256 B邮箱里只有20 B有效消息，可以访问有效内容，再按接口规则访问邮箱末字节以完成握手；并非协议一律要求把中间236 B逐字节补零。整块访问256 B也是一种实现。

以上按正常的“读末字节完成读访问”方式说明。支持并启用 **PDI register function acknowledge by Write** 的实现，用写末地址完成 PDI 读缓冲的确认；不能把普通方式的结束动作直接套过去。

## Status：完成通知不等于读方已经读完

| 位 | 含义及清除时机 |
| --- | --- |
| bit0 | 完整、成功写入后的 Write Event；读方读首字节后清除 |
| bit1 | 完整、成功读取后的 Read Event；写方写首字节后清除 |
| bit3 | 仅邮箱模式有效：0为空，1为满 |
| bit5:4 | 仅三缓冲有效：`00/01/10` 为最后写入的第1/2/3份缓冲，`11` 为尚无写入 |

bit0 通知读方，bit1 通知写方。因此 SM2 为 ECAT写/PDI读时，写完成可以通知 MCU，读完成可以通知主站；方向反过来，通知对象也反过来。

首字节被读取后事件清除，只能说明读取已经开始，不能证明消息已被读完。bit5:4 供观察，软件仍访问同一个窗口，不按该编号自行选择缓冲地址。

ET1100 的 bit2、bit6、bit7 保留。某些其他 ESC 用 bit6/bit7 显示读/写缓冲已打开；抓到状态 `0x80` 时，必须先确认芯片定义，不能套成 ET1100 的邮箱已满。

## Activate 与 PDI Control

Activate.bit0=1 让 SM 管理指定内存；清零则解除这一 SM 的访问管理。
PDI Control.bit0 则是本地应用请求停用并复位 SM，会锁住该区域的访问；请求可能延迟到当前帧结束生效。二者不能视为同一种“关闭”。

邮箱重传用一组翻转握手：主站翻转 Activate.bit1（Repeat Request），PDI 按邮箱协议重做所需操作，再把 PDI Control.bit1（Repeat Ack）设为相同值。它主要用于 ECAT 读邮箱，不是一般 PDO 重发开关。

Activate.bit6/bit7 是 **Latch Event ECAT/PDI 配置使能**。它们允许相应侧的缓冲交换，以及 PDI 缓冲起始访问，触发 DC 时间记录；不是硬件完成交换后才自动置1的状态位。相关时间在 `0x09F0`、`0x09F8`、`0x09FC`，用于观察交接时序，详见[SYNC 与 Latch](../../../时钟同步/SYNC与Latch/SYNC与Latch.md)。

从状态位到真正中断还须经过使能和屏蔽，见[事件与中断](../../../诊断与调试/事件与中断/事件与中断.md)。
