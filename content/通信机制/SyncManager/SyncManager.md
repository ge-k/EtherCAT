# SyncManager

**SyncManager（SM）** 是 ESC 内部管理共享数据访问的硬件。主站从 EtherCAT 侧访问 RAM，MCU 从 PDI 侧访问 RAM；SM 规定双方的方向、访问条件以及一批数据何时完成。

例如主站更新 4 字节目标位置时，MCU 若直接读同一块未受保护的 RAM，可能读到前两字节是新值、后两字节还是旧值。SM 的作用是让双方按规定交换完整数据。

## 一个 SM 通道配置什么

SM 通道通常配置起始地址、长度、读写方向、工作模式、激活状态，以及事件和看门狗相关选项。ET1100 的 SM 配置区从 `0x0800` 开始。

一个通道有规定的数据方向：一侧写，另一侧读。双向通信通常使用不同通道。SM 同步的是**内存访问和数据交接**，并不直接把多个从站的时钟同步到同一时刻；后者由 [DC](../../时钟同步/DC时钟/DC时钟.md)处理。

## 缓冲模式：完整且尽可能新的过程数据

过程数据常使用三缓冲模式。可以把三块缓冲理解为正在写入、正在读取、等待交换三种角色。SM 根据访问完成情况交换角色，无须为了切换角色把整块数据复制三遍。

写方可以继续发布新版本，读方正在使用的那一份则保持一致。如果写方更新得比读方快，中间版本可以被较新的完整版本替代。

```text
主站依次发布：1000 → 1010 → 1020 rpm
MCU 本次可能直接读到完整的 1020 rpm
不要求先把没有消费过的 1010 rpm 补读一遍
```

“最新”指读方取得缓冲时可用的完整版本。读取已经开始之后，不能为了追逐新值而把正在读取的缓冲中途换掉；也不保证一个跨多个 SM 的大数据集合天然属于同一采样时刻。

三缓冲同样有访问完成判定和可配置的 SM 事件。它与邮箱的区别是没有采用邮箱那种“满后必须先读空，才能再次写入”的逐封握手，不能说三缓冲没有完成事件。

## 邮箱模式：消费后再交下一封

Mailbox 模式通常使用单缓冲握手：

```text
发送方完成一封消息的写入
→ 缓冲标记为满，阻止后续消息覆盖
→ 接收方读走消息并完成读访问
→ 缓冲恢复可写
```

这适合参数请求、文件传输等消息，因为接收方不能尚未读走命令，发送方就用下一条覆盖它。具体哪次访问触发满、空和完成，由 SM 的访问规则判定；软件要正确访问配置区域及结束位置。

“接收方读走邮箱”也不等于“上层请求执行成功”。例如 SDO 写参数还要检查相应 SDO 响应，见[邮箱与 CoE](../邮箱与CoE/邮箱与CoE.md)。

## 常见通道分配

| 通道 | 典型方向 | 典型用途 |
| --- | --- | --- |
| SM0 | 主站写、从站应用读 | 主站到从站的邮箱 |
| SM1 | 从站应用写、主站读 | 从站到主站的邮箱 |
| SM2 | 主站写、从站应用读 | 主站过程输出 |
| SM3 | 从站应用写、主站读 | 主站过程输入 |

编号和用途不是固定绑定，实际分配由设备描述及主站配置决定。笔记中的邮箱实例使用 `0x1000～0x13FF` 和 `0x1400～0x17FF`，每个方向长度 1024 B；这不是所有设备通用的邮箱地址。

SM 管理缓冲访问，[FMMU](../FMMU/FMMU.md)负责地址映射，二者相互配合。SM 不是数据写入 RAM 后再经过的另一个搬运模块。
