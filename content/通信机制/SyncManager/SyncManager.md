# SyncManager

**SyncManager（SM）** 是 ESC 内部管理共享数据访问的硬件。
主站从 EtherCAT 侧访问 RAM，MCU 从 PDI 侧访问 RAM。
SM 规定双方的方向、访问条件以及一批数据何时完成。

例如主站更新 4 字节目标位置时，MCU 若直接读同一块未受保护的 RAM，可能读到前两字节是新值、后两字节还是旧值。SM 的作用是让双方按规定交换完整数据。

## 一个 SM 通道配置什么

配置项：
起始地址、长度、读写方向、工作模式、激活状态，以及事件和看门狗相关选项。
ET1100 的 SM 配置区从 `0x0800` 开始。

一个 SM 通道有规定的数据方向：一侧专门写，另一侧专门读。

## 缓冲模式：完整且尽可能新的过程数据

过程数据常使用三缓冲模式。
正在写入、正在读取、等待交换三种角色，SM 根据访问完成情况，交换角色。

写方可以继续发布新版本，读方正在使用的那一份则保持一致。
如果写方更新得比读方快，中间版本可以被较新的完整版本替代。

```text
主站依次发布：1000 → 1010 → 1020 rpm
MCU 本次可能直接读到 1020 rpm
不要求先把没有消费过的 1010 rpm 补读一遍
```

“最新”指读方取得缓冲时可用的完整版本。
读取已经开始之后，不能为了追逐新值而把正在读取的缓冲中途换掉。

三缓冲同样有 访问完成判定 和 可配置的 SM 事件。
没有采用邮箱那种“满后必须先读空，才能再次写入”的逐封握手，不能说三缓冲没有完成事件。

## 邮箱模式：消费后再交下一封

Mailbox 模式通常使用单缓冲握手：

```text
发送方完成一封消息的写入
→ 缓冲标记为满，阻止后续消息覆盖
→ 接收方读走消息，并完成读访问
→ 缓冲恢复可写
```

这适合参数请求、文件传输等消息。
接收方不能尚未读走命令，发送方就用下一条覆盖它。

“接收方读走邮箱”也不等于“上层请求执行成功”。
例如 SDO 写参数还要检查相应 SDO 响应，见[邮箱与 CoE](../邮箱与CoE/邮箱与CoE.md)。

## 常见通道分配

| 通道  | 典型用途     |
| --- | -------- |
| SM0 | 主站到从站的邮箱 |
| SM1 | 从站到主站的邮箱 |
| SM2 | 主站过程输出   |
| SM3 | 主站过程输入   |

编号和用途不是固定绑定，实际分配由设备描述、主站配置决定。

[FMMU](../FMMU/FMMU.md)负责地址映射，SM 管理缓冲访问，二者相互配合。
SM 不是数据写入 RAM 后再经过的另一个搬运模块，SM 本身不是 RAM。
写 SM0，是往SM0 管理的 DPRAM 写
