# AL 状态机

AL（Application Layer）状态机规定 从站通信功能 开放到哪一步。
它把“链路能访问”“可以配置参数”“可以读取输入”“可以正常应用输出”分成不同阶段。

## 四个主要状态

```text
INIT → PRE-OP → SAFE-OP → OP
```

| 状态      | 值      | 主要功能                                            |
| ------- | ------ | ----------------------------------------------- |
| INIT    | `0x01` | 建立基础访问和初始化，正常邮箱及过程数据通信未开放                       |
| PRE-OP  | `0x02` | 支持的邮箱通信可用，进行参数和 PDO 配置                          |
| SAFE-OP | `0x04` | 输入过程数据可更新；<br>主站可提供输出数据，但从站不会应用，实际输出通常保持规定的安全状态 |
| OP      | `0x08` | 满足设备条件时，正常应用输出，持续读取输入反馈                         |

支持 Boot 状态的设备，还可提供专门的固件传输路径；
不能由某设备支持邮箱，就推断它在所有状态，都支持所有邮箱协议。

PRE-OP 中支持 CoE 的设备可以通过 SDO 配置参数，见[邮箱与 CoE](../../通信机制/邮箱与CoE/邮箱与CoE.md)。
SAFE-OP 中已经可以开始周期数据交换，并非一定要等到 OP 才有周期帧。

## 请求与确认

| 寄存器            | 地址       | 谁用它做什么           |
| -------------- | -------- | ---------------- |
| AL Control     | `0x0120` | 主站请求 目标状态及相关控制   |
| AL Status      | `0x0130` | 从站报告 当前状态和错误标志   |
| AL Status Code | `0x0134` | 提供 状态迁移或运行异常 的原因 |

一次状态迁移是：

```text
主站请求目标状态
→ 从站检查所需配置和应用条件
→ 成功则确认状态；失败则报告错误原因
→ 主站读取状态，确认结果
```

对于带 MCU 的从站，协议栈和应用参与检查，不能认为 ESC 硬件自动批准全部状态迁移。

INIT → PRE-OP 通常要满足邮箱初始化条件；
PRE-OP → SAFE-OP 要满足 过程数据及所选同步模式 的要求。
对于有输出的从站，主站在请求 OP 前，应先提供有效输出数据，并持续满足同步和看门狗条件。

## SAFE-OP 中的输入、输出分别是什么

| 名称              | 方向及内容                | 在哪里交接                       |
| --------------- | -------------------- | --------------------------- |
| 从站->主站<br>TxPDO | 从站返回实际位置、状态字等        | MCU 经 PDI 发布到 ESC，<br>主站再读走 |
| 主站->从站<br>RxPDO | 主站发送目标位置、控制字等        | 主站写入 ESC，<br>MCU 经 PDI 读取   |
| 设备实际输出          | 从站对本地电机、数字输出引脚等的控制作用 | 由本地应用与输出硬件执行                |

假设一台伺服的 TxPDO 配置为：
```
前 2 字节：状态字
后 4 字节：实际位置
```
“从站准备有效输入”可以具体理解成：
```
从站 MCU 获取当前状态，比如，状态是驱动器尚未使能
    ↓
获取当前实际位置，编码器位置为 12345
    ↓
按配置的 TxPDO 布局组织这 6 字节
[状态字 2 字节][实际位置 4 字节]
    ↓
通过 PDI 写入 ESC 中 供主站读取的 过程数据缓冲区
    ↓
主站读取时，能得到这些 有实际含义的数据
```
**电机没有运动，也有当前状态和当前位置，所以可以先提供反馈，不必先收到目标位置。**
“有效”强调的是：
按约定布局，提供已**正确初始化、符合设备要求**的数据，不能把**尚未初始化的内容**当作反馈。**它不表示电机已经使能，也不表示已经到达目标。**


对于有 过程输出 的从站，一个典型过程是：
1. 主站写 AL Control 请求 SAFE-OP；
   从站检查 过程数据、同步、应用条件，并准备输入数据通道。
2. 从站报告 AL Status 为 SAFE-OP，主站读取并确认迁移成功。
3. 在 SAFE-OP 中，主站可以读取 TxPDO，也可发送准备给从站的 RxPDO，
   例如初始控制字、初始目标值。这就是进入 OP 前提供有效输出数据。
4. 从站可以接收这些过程数据，但通常保持本地实际输出为设备规定的安全值，不立即按新命令驱动设备。
5. 主站已提供所需有效输出，并满足 同步等 条件后，请求 OP；
   从站检查通过，报告 OP。此后从站按 配置模式、自身应用条件 正常采用主站命令。

以数字输出模块为例，设备若规定 SAFE-OP 的安全值为 0，即使 RxPDO 中已经收到某位为 1，实际引脚仍保持 0；进入 OP 并满足设备条件后，才允许按该位控制引脚。这里必须区分“数据已写进 ESC”和“命令已作用到实际设备”。

## 三个容易混淆的状态

**Link up** 只表示物理链路已建立，可以出现 Link 正常，但从站仍在 INIT 的情况。

**EtherCAT OP** 表示通信应用状态已开放，不等于伺服驱动器已使能。

**SAFE-OP 的安全输出**是设备定义的行为，不自动等于 设备或整机 已经满足功能安全要求。

## 无法进入 OP 时怎样定位

先确认卡在哪一次迁移，再读取 AL Status 和 AL Status Code。
常见问题涉及邮箱地址或长度、SM 配置、PDO 长度、无有效输出、看门狗或 DC 同步配置。

广播读取 AL Status 会按位 OR 汇总各站结果；
它适合发现状态不一致，具体哪台异常则要逐站读 AL Status。
底层访问是否成功还要结合 [WKC](../../诊断与调试/WKC/WKC.md)。
