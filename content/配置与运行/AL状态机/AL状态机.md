# AL 状态机

AL（Application Layer）状态机规定从站通信功能开放到哪一步。它把“链路能访问”“可以配置参数”“可以交换输入”“可以正常应用输出”分成不同阶段。

## 四个主要状态

```text
INIT → PRE-OP → SAFE-OP → OP
```

| 状态 | 值 | 主要功能 |
| --- | --- | --- |
| INIT | `0x01` | 建立基础访问和初始化，正常邮箱及过程数据通信未开放 |
| PRE-OP | `0x02` | 支持的邮箱通信可用，进行参数和 PDO 配置 |
| SAFE-OP | `0x04` | 输入过程数据可更新；主站可提供输出数据，但实际输出通常保持规定的安全状态 |
| OP | `0x08` | 满足设备条件时正常应用输出，持续交换输入反馈 |

支持 Boot 状态的设备还可提供专门的固件传输路径；不能由某设备支持邮箱就推断它在所有状态都支持所有邮箱协议。

PRE-OP 中支持 CoE 的设备可以通过 SDO 配置参数，见[邮箱与 CoE](../../通信机制/邮箱与CoE/邮箱与CoE.md)。SAFE-OP 中已经可以开始周期数据交换，并非一定要等到 OP 才有周期帧。

## 请求与确认

| 寄存器 | 地址 | 谁用它做什么 |
| --- | --- | --- |
| AL Control | `0x0120` | 主站请求目标状态及相关控制 |
| AL Status | `0x0130` | 从站报告当前状态和错误标志 |
| AL Status Code | `0x0134` | 提供状态迁移或运行异常的原因 |

一次状态迁移是：

```text
主站请求目标状态
→ 从站检查所需配置和应用条件
→ 成功则确认状态；失败则报告错误原因
→ 主站读取状态，确认结果
```

对于带 MCU 的从站，协议栈和应用参与检查，不能认为 ESC 硬件自动批准全部状态迁移。

INIT → PRE-OP 通常要满足邮箱初始化条件；PRE-OP → SAFE-OP 要满足过程数据及所选同步模式的要求。对于有输出的从站，主站在请求 OP 前应先提供有效输出数据，并持续满足所需同步和看门狗条件。

## SAFE-OP 中的输入、输出分别是什么

这里的输入、输出以主站为参照。以伺服为例：

| 名称 | 方向及内容 | 在哪里交接 |
| --- | --- | --- |
| 主站输入，即从站 TxPDO | 从站返回实际位置、状态字等 | MCU 经 PDI 发布到 ESC，主站再读走 |
| 主站输出，即从站 RxPDO | 主站发送目标位置、控制字等 | 主站写入 ESC，MCU 经 PDI 读取 |
| 设备实际输出 | 从站对本地电机、数字输出引脚等的控制作用 | 由本地应用与输出硬件执行 |

**“从站准备有效输入”** 是让输入数据通道具备提供正确初始化、符合当前 PDO 布局的数据的条件，例如有效的状态字、按设备要求取得的位置反馈；具体内容由设备定义。它不是要求主站先给从站发目标，也不表示电机必须先运动过。

**“从站确认状态”** 是从站接受状态迁移、通过 AL Status 报告已经进入 SAFE-OP；主站还需读回确认。状态确认与 PDO 数据是两种不同信息。

对于有过程输出的从站，一个典型过程是：

1. 主站写 AL Control 请求 SAFE-OP；从站检查过程数据、同步和应用条件，并准备输入数据通道。
2. 从站报告 AL Status 为 SAFE-OP，主站读取并确认迁移成功。
3. 在 SAFE-OP 中，主站可以读取 TxPDO，也可发送准备给从站的 RxPDO，例如初始控制字和目标值。这就是进入 OP 前提供有效输出数据。
4. 从站可以接收这些过程数据，但通常保持本地实际输出为设备规定的安全值，不立即按新命令驱动设备。
5. 主站已提供所需有效输出，并满足同步等条件后，请求 OP；从站检查通过，报告 OP。此后从站按配置模式及自身应用条件正常采用主站命令。

“有效输出”要求主站按已配置的布局和长度，通过规定的数据通道提供可接受的数据，并满足设备要求的更新和同步条件。初始值应适合当前设备状态，不能一概认定“全部填零”就是有效且合适的输出。

以数字输出模块为例，设备若规定 SAFE-OP 的安全值为 0，即使 RxPDO 中已经收到某位为 1，实际引脚仍保持 0；进入 OP 并满足设备条件后，才允许按该位控制引脚。这里必须区分“数据已写进 ESC”和“命令已作用到实际设备”。

## 三个容易混淆的状态

**Link up** 只表示物理链路已建立，可以出现 Link 正常但从站仍在 INIT 的情况。

**EtherCAT OP** 表示通信应用状态已开放，不等于伺服驱动器已使能。使用 CiA 402 的驱动器还需满足驱动状态机、模式、控制字和联锁等条件。

**SAFE-OP 的安全输出**是设备定义的行为，不自动等于设备或整机已经满足功能安全要求。

## 无法进入 OP 时怎样定位

先确认卡在哪一次迁移，再读取 AL Status 和 AL Status Code。常见问题涉及邮箱地址或长度、SM 配置、PDO 长度、无有效输出、看门狗或 DC 同步配置。

广播读取 AL Status 会按位 OR 汇总各站结果；它适合发现状态不一致，具体哪台异常则要逐站读。底层访问是否成功还要结合 [WKC](../../诊断与调试/WKC/WKC.md)。
