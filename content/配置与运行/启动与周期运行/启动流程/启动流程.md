# 启动流程

以下以 ET1100、外部 SII EEPROM 和 MCU 组成、支持 CoE 的从站为例，
说明主站配置与从站应用怎样配合。

## 上电与识别

电源、时钟和复位满足要求后，ESC 加载 SII 启动配置，PDI 具备可用条件。
MCU 初始化 本地应用、从站协议栈。
外部 PHY 建立链路。
ESC 按端口状态转发或回环。

随后主站广播探测并按位置访问，
分配配置站地址，读取 ESC 能力、端口状态、设备身份，与预期工程匹配。
启动信息的具体位置见[SII 与 ESI](../../设备描述/SII与ESI/SII与ESI.md)。

Link 正常只是这条过程的起点；设备身份、拓扑和应用状态还要继续确认。

## 建立邮箱并配置过程数据

主站在 INIT 中，配置设备所需的邮箱 SM，然后请求并确认 PRE-OP。
支持 CoE 的设备在 PRE-OP 阶段可以通过 SDO 访问参数。

主站确定 RxPDO、TxPDO 的内容、顺序和长度；
可配置设备，按需修改映射，
固定映射设备，按规定使用。
然后配置过程数据 SM 和 FMMU，使业务布局、内部缓冲区和逻辑地址一致。

```text
PDO：要交换什么
SM：两侧怎样交换完整的数据
FMMU：逻辑地址落到本站哪里
```

各机制的详细规则分别放在 [PDO](../../../通信机制/PDO/PDO.md)、[SyncManager](../../../通信机制/SyncManager/基本原理/基本原理.md)和 [FMMU](../../../通信机制/FMMU/FMMU.md)中。

## 同步与状态开放
需要 DC 时，主站先识别支持能力和拓扑，选择参考时钟，
测算传播延迟delay和初始偏移offset，并持续发送 同步报文，防止时钟因晶振差异再次偏离。
使用 SYNC0/SYNC1 时，还需配置它们的启动时间、周期等参数。
**同步报文：** 主站发送访问 `0x0910` 的 FRMW，把参考站的时间传给其他 DC 从站，让它们校正时钟误差，0x0910~0x0917 是 DC System Time（系统时间）
  

过程数据 及 所选同步模式配置完成后，主站请求 SAFE-OP；
从站检查条件，并通过 AL Status 报告迁移结果。
主站读取状态，确认从站已经进入 SAFE-OP。

输出是RxPDO，主站发给从站的控制字、目标值。
输入是TxPDO，站发回的状态、测量值
SAFE-OP 中可以更新输入数据，也可以接收主站为进入 OP 准备的输出数据，但从站通常还不把这些输出命令正常作用到实际 IO 或电机。

例如数字输出模块已经收到“置某输出位为 1”的 PDO 数据，在 SAFE-OP 中仍可能按设备规定将实际引脚保持为 0。进入 OP 并满足应用条件后，才允许按收到的数据控制该引脚。伺服进入 OP 后还需满足驱动使能等自身条件。

各状态的输入准备、有效初始输出和迁移确认，见 [AL 状态机](../../AL状态机/AL状态机.md)。


## 从扫描到 OP 的报文阅读顺序

以下按两台支持 CoE、使用 DC 的设备说明依赖关系。主站可以提前测量 DC 或穿插状态轮询，不存在所有实现都必须遵守的固定帧号。

| 阶段 | 网络操作与判断 |
| --- | --- |
| 发现 | BRD 检查参与站数和状态，APWR 分配配置站地址，之后用 FPRD/FPWR |
| 读取能力 | 读资源数量、端口 Link/Loop、SII 身份和描述；按需触发并读取 DC 接收时间 |
| 初始化 | 请求并确认 INIT，按设备资源数量清理或重建 FMMU、SM，停用旧 SYNC 配置 |
| 建立邮箱 | 配置 SM0/SM1 的起点、长度、模式、方向，处理 EEPROM 控制归属，确认 PRE-OP |
| 确定 PDO | SDO 查询或设置分配与映射，计算每个方向长度 |
| 配置运行 | 写过程数据 SM、FMMU、看门狗；需要 DC 时写 offset/delay并安排 SYNC |
| 开放输入 | 请求 SAFE-OP，逐站确认 AL Status |
| 准备输出 | 持续提供有效 RxPDO，保证所选同步模式的时间条件 |
| 请求 OP | 写 AL Control，然后轮询 AL Status；等待从站完成应用检查 |
| 周期运行 | 交换过程数据，维持校时，检查 WKC、AL 状态及诊断信息 |

扫描阶段为读取 SDO 建立过一次邮箱，运行阶段仍可能重新请求 INIT 并建立配置。这是主站实现选择，不是协议强制重复若干轮；请求 INIT 也不等于 MCU 复位或清零所有 ESC 寄存器。

可以在同一帧中先放 LWR、再放请求 OP 的 BWR。但 SM 发布仍受整帧校验约束，不能仅凭子报文顺序推断 MCU 已经处理完输出。主站随后仍要持续交换数据并等待从站确认。

## SYNC 已运行而 PDO 尚未发送

ESC 的 SYNC0 由 DC 定时单元产生，SM2 输出事件由实际输出写访问产生。因此两台从站停在 SAFE-OP、SYNC0已经激活，却尚无周期 LWR，完全可能。

SAFE-OP 不会统一屏蔽 PDI 中断；它限制正常输出应用到设备。主站没写输出与硬件禁止输出事件，是不同原因。进入 OP 可能还要等待从站协议栈的同步有效检查，等待时长由实现决定，不存在所有 EtherCAT 从站通用的200 ms门槛。

进入运行后的取数、采样和输出时序见[周期运行](../周期运行/周期运行.md)。
