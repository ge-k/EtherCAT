# 周期运行

从站完成启动并具备所需通信条件后，网络数据交换与本地控制仍是两个配合的流程。

## 运行中的通信线与应用线

通信线，由主站与 ESC 完成：

```text
主站准备输出过程映像，并组织报文
→ 对命中的写访问，ESC 把 主站输出数据 写入 SM 管理的过程数据缓冲区
→ 对命中的读访问，ESC 把已准备好的 主站输入数据 填入 Datagram Data
→ ESC 更新 WKC 并继续转发
→ 帧返回，主站检查参与情况和状态
```

不规定每次都先写后读。LWR 只写，LRD 只读，LRW 可以在一次访问中交换两个方向的数据；

应用线，由从站任务和控制硬件完成，需要区分三个动作：

```text
取主站命令：ESC 的 RxPDO 对应缓冲区 → PDI → MCU
控制本地设备：MCU → PWM、DAC 或实际 IO
发布主站反馈：MCU 准备状态、采样值等 → PDI → ESC 的 TxPDO 对应缓冲区
```

这三个动作需要配合，
但不是每收到一条命令就必须按同一个顺序一次做完。
控制算法可能先采样当前位置再计算，
电机控制中断也可能比 EtherCAT 周期运行得更快。

**把反馈写入 ESC，供主站读取，不等于把控制结果输出给电机。**

两条线相互交换数据，但 ESC 不会停住报文，等待 MCU 计算或电机到位。
因此，“这帧写入目标，同时读回输入”不表示读回了这个目标执行完成后的结果。

## 应用处理由什么触发

| 模式      | 应用节拍                         |
| ------- | ---------------------------- |
| 自由运行    | 从站自己的任务或定时器                  |
| SM 事件同步 | 配置的 过程数据 读写事件                |
| DC 同步   | 共同时间基准下的 SYNC0/SYNC1 及设备规定时序 |

DC 模式
1. 可以在 SM 输出事件通知后，先取数，直接计算，到 SYNC0 时应用准备好的结果；
2. 也可以在 SYNC0 时取数或采用先前保存的目标，再采样、计算和更新控制。

`PDI_ISR`、`SYNC0_ISR`是固件中的中断处理函数名，不是 EtherCAT 规定的固定处理流程。
PDI 中断可能来自多种 AL 事件，必须检查来源，不能每次进入都认为有新的 RxPDO。
SYNC0 也只有按硬件连线和配置接入 MCU 中断，才会进入相应处理函数。

采用哪种方式，要与设备支持的同步模式、控制算法 和 处理时间匹配。
例如算法需要**同步时刻采样的电流**，就**不能**在此前把**依赖这次采样的运算**全部完成。

事件是否转成 MCU 中断还取决于配置，应用也可能轮询。

## 三轴目标与反馈的例子

假设三台伺服均已 OP、驱动已使能且 DC 同步。
这里采用：
收到输出事件后先读取目标并完成可提前做的准备，在 SYNC0 时采用该目标；
在**配置的采样时刻**取得反馈，准备完成后发布给主站。

```text
主站 LWR/LRW 到达
→ ESC 将本站目标写入 RxPDO 对应缓冲区
→ 已使能的 SM 输出事件通过 PDI IRQ 通知 MCU
→ PDI_ISR 检查事件，经 PDI 取走完整目标
→ MCU 保存目标、完成允许提前做的计算，准备好下一次更新所需的数据

约定的 DC 时间到达
→ ESC 产生 SYNC0，按配置通知 MCU
→ 采用已准备的目标或结果，更新本地控制
→ 本地 PWM / IO 等在其硬件允许的更新时刻生效

到达设备规定的反馈采样时刻
→ 取得实际位置等测量值，并准备状态字
→ MCU 经 PDI 将一份完整反馈发布到 TxPDO 对应缓冲区
→ 后续 LRD/LRW 读取发布完成后可用的反馈
```

反馈采样可以安排在同步处理的开始、结束或其他规定时刻，
不是一定等控制输出更新之后才采样。
反馈写入 ESC 可以在 SYNC0_ISR 内完成，也可以由其他任务完成；
前提是满足设备所选模式及主站读取的时间要求。

如果一个实现把**采样、计算、反馈**都安排在 SYNC0_ISR 中，也是一种明确的实现。

## 反馈何时能被主站读到

主站取得哪份反馈，取决于 **MCU 发布完整反馈** 与 **LRD/LRW 到达** 的先后关系。例如总线周期为 1 ms：

| 时刻      | 动作                              |
| ------- | ------------------------------- |
| 0.00 ms | LRW（读写） 到达，写入本轮目标，同时读取此前已经发布的反馈 |
| 0.30 ms | SYNC0 到来，执行本例配置的同步任务            |
| 0.35 ms | MCU 完成并发布一份新反馈到 ESC             |
| 1.00 ms | 下一条 LRW 到达，可读取这份新反馈             |

在这个具体安排中，
0.35 ms 发布的反馈由下一轮 LRW 读走。
如果同一周期 0.50 ms 还安排了一条 LRD，它就有机会提前读走；
如果新反馈直到 1.00 ms 的读访问之后才发布，则该次读访问仍只能取得此前的完整版本。

所以，EtherCAT 不统一规定“本轮发送目标，下一轮必定返回这个目标对应的反馈”。
尤其实际位置只是采样时电机的位置，不表示电机已经运动到本轮目标。
MCU 处理、PWM 生效和机械运动分别有自己的耗时。

运行期间，主站继续检查 
WKC（返回的 Datagram 中）、
AL 状态（读取 ESC 寄存器，AL Status 寄存器，`0x0130`）、
DC 误差（读取 ESC 寄存器，System Time Difference 寄存器，`0x092C`）。

运行期间，从站通过[看门狗](../../../诊断与调试/看门狗/看门狗.md)、应用机制，处理超时或故障。

## 硬件看门狗与软件同步检查

硬件过程数据看门狗检查规定的输出写访问是否持续发生；固件还可独立检查 SYNC0 是否得到及时处理，以及 SM 输出事件是否按要求出现在 SYNC0 前后。这些检查的观察对象和时间窗口不同。

例如硬件看门狗为100 ms，而同步周期为1 ms，软件可能在更早的若干周期内发现同步异常并退回 SAFE-OP。不能据此推断硬件看门狗失效，或它的错误分支永远无用。

AL Status Code `0x001A` 表示同步错误，`0x001B` 表示 SyncManager 看门狗相关错误；具体何种条件设置这些代码、请求 OP 时怎样等待以及运行时怎样退出，须查对应固件版本。网卡抓包不能直接证明 `PDI_Isr()`、SYNC0处理函数或内部计数变量执行过什么。
