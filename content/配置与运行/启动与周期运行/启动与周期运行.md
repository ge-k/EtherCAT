# 启动与周期运行

以下以 ET1100、外部 SII EEPROM 和 MCU 组成、支持 CoE 的从站为例，
说明主站配置与从站应用怎样配合。

## 上电与识别

电源、时钟和复位满足要求后，ESC 加载 SII 启动配置，PDI 具备可用条件。
MCU 初始化本地应用与从站协议栈。
外部 PHY 建立链路。
ESC 按端口状态转发或回环。

随后主站广播探测并按位置访问，
分配配置站地址，读取 ESC 能力、端口状态、设备身份，与预期工程匹配。
启动信息的具体位置见[设备描述](../设备描述/设备描述.md)。

Link 正常只是这条过程的起点；设备身份、拓扑和应用状态还要继续确认。

## 建立邮箱并配置过程数据

主站在 INIT 中配置设备所需的邮箱 SM，然后请求并确认 PRE-OP。
支持 CoE 的设备在此阶段可以通过 SDO 访问参数。

主站确定 RxPDO、TxPDO 的内容、顺序和长度；
可配置设备，按需修改映射，
固定映射设备，按规定使用。
然后配置过程数据 SM 和 FMMU，使业务布局、内部缓冲区和逻辑地址一致。

```text
PDO：要交换什么
SM：两侧怎样交换完整的数据
FMMU：逻辑地址落到本站哪里
```

各机制的详细规则分别放在 [PDO](../../通信机制/PDO/PDO.md)、[SyncManager](../../通信机制/SyncManager/SyncManager.md)和 [FMMU](../../通信机制/FMMU/FMMU.md)中。

## 同步与状态开放
需要 DC 时，主站先识别支持能力和拓扑，选择参考时钟，
测算传播延迟delay和初始偏移offset，并持续发送 同步报文，防止时钟因晶振差异再次偏离。
使用 SYNC0/SYNC1 时，还需配置它们的启动时间、周期等参数。
**同步报文：** 主站发送访问 `0x0910` 的 FRMW，把参考站的时间传给其他 DC 从站，让它们校正时钟误差，0x0910~0x0917 是 DC System Time（系统时间）
  



过程数据 及 所选同步模式配置完成后，主站请求 SAFE-OP；
从站检查条件并通过 AL Status 报告迁移结果。
**请求 SAFE-OP 和已经进入 SAFE-OP 是两个步骤。** 
主站读取状态，确认从站已经进入 SAFE-OP，随后可以按该状态允许的方式交换过程数据。

这里的“输入”和“输出”以主站为参照：输入是从站发回的状态、测量值等 TxPDO 数据；输出是主站发给从站的控制字、目标值等 RxPDO 数据。SAFE-OP 中可以更新输入数据，也可以接收主站为进入 OP 准备的输出数据，但从站通常还不把这些输出命令正常作用到实际 IO 或电机。

例如数字输出模块已经收到“置某输出位为 1”的 PDO 数据，在 SAFE-OP 中仍可能按设备规定将实际引脚保持为 0。进入 OP 并满足应用条件后，才允许按收到的数据控制该引脚。伺服进入 OP 后还需满足驱动使能等自身条件。

各状态的输入准备、有效初始输出和迁移确认，见 [AL 状态机](../AL状态机/AL状态机.md)。

## 运行中的通信线与应用线

通信线，由主站与 ESC 完成：

```text
主站准备输出过程映像，并组织报文
→ 对命中的写访问，ESC 把主站输出数据写入 SM 管理的过程数据缓冲区
→ 对命中的读访问，ESC 把已准备好的主站输入数据填入 Datagram Data
→ ESC 更新 WKC 并继续转发
→ 帧返回，主站检查参与情况和状态
```

上面的读、写表示两种访问作用，不规定每次都先写后读。LWR 只写，LRD 只读，LRW 可以在一次访问中交换两个方向的数据；是否参与取决于地址、映射和访问条件。

应用线，由从站任务和控制硬件完成，需要区分三个动作：

```text
取主站命令：ESC 的 RxPDO 对应缓冲区 → PDI → MCU
控制本地设备：MCU / 控制硬件 → PWM、DAC 或实际 IO
发布主站反馈：MCU 准备状态、采样值等 → PDI → ESC 的 TxPDO 对应缓冲区
```

这三个动作需要配合，但不是每收到一条命令就必须按同一个顺序一次做完。控制算法可能先采样当前位置再计算，电机控制中断也可能比 EtherCAT 周期运行得更快。

**把反馈写入 ESC，供主站读取，不等于把控制结果输出给电机。** 本例采用外部 MCU 控制电机；直接数字 IO PDI 等实现的输出路径不同。

两条线相互交换数据，但 ESC 不会停住报文，等待 MCU 计算或电机到位。
因此，“这帧写入目标，同时读回输入”不表示读回了这个目标执行完成后的结果。

## 应用处理由什么触发

| 模式      | 应用节拍                         |
| ------- | ---------------------------- |
| 自由运行    | 从站自己的任务或定时器                  |
| SM 事件同步 | 配置的过程数据读写事件                  |
| DC 同步   | 共同时间基准下的 SYNC0/SYNC1 及设备规定时序 |

DC 模式可以在 SM 输出事件通知后先取数、进行适合提前完成的计算，到 SYNC0 时应用准备好的结果；也可以在 SYNC0 时取数或采用先前保存的目标，再采样、计算和更新控制。

`PDI_ISR`、`SYNC0_ISR`（有些代码写作 `SYNC_ISR`）是固件中的中断处理函数名，不是 EtherCAT 规定的固定处理流程。PDI 中断可能来自多种 AL 事件，必须检查来源，不能每次进入都认为有新的 RxPDO。SYNC0 也只有按硬件连线和配置接入 MCU 中断，才会进入相应处理函数。

采用哪种方式，要与设备支持的同步模式、控制算法和处理时间匹配。例如算法需要同步时刻采样的电流，就不能在此前把依赖这次采样的运算全部完成。

事件是否转成 MCU 中断还取决于配置，应用也可能轮询。

## 三轴目标与反馈的例子

假设三台伺服均已 OP、驱动已使能且 DC 同步。这里明确选用一种实现：收到输出事件后先读取目标并完成可提前做的准备，在 SYNC0 时采用该目标；反馈在配置的采样时刻取得，准备完成后发布给主站。

```text
主站 LWR/LRW 到达
→ ESC 将本站目标写入 RxPDO 对应缓冲区
→ 已使能的 SM 输出事件通过 PDI IRQ 通知 MCU
→ PDI_ISR 检查事件，经 PDI 取走完整目标
→ MCU 保存目标、完成允许提前做的计算，准备好下一次更新所需的数据

约定的 DC 时间到达
→ ESC 产生 SYNC0，按配置通知 MCU / 控制硬件
→ 在本例的同步处理过程中，采用已准备的目标或结果，更新本地控制
→ 本地 PWM / IO 等在其硬件允许的更新时刻生效

到达设备规定的反馈采样时刻
→ 取得实际位置等测量值，并准备状态字
→ MCU 经 PDI 将一份完整反馈发布到 TxPDO 对应缓冲区
→ 后续 LRD/LRW 读取发布完成后可用的反馈
```

反馈采样可以安排在同步处理的开始、结束或其他规定时刻，不是一定等控制输出更新之后才采样。反馈写入 ESC 可以在 SYNC0_ISR 内完成，也可以由其他任务完成；前提是满足设备所选模式及主站读取的时间要求。

如果一个实现把采样、计算和反馈发布都安排在 SYNC0_ISR 中，也是另一种明确的实现，不能仅从“用了 DC”推断函数内执行顺序。

## 反馈何时能被主站读到

主站取得哪份反馈，取决于 **MCU 发布完整反馈** 与 **LRD/LRW 到达** 的先后关系。例如总线周期为 1 ms：

| 时刻 | 动作 |
| --- | --- |
| 0.00 ms | LRW 到达，写入本轮目标，同时读取此前已经发布的反馈 |
| 0.30 ms | SYNC0 到来，执行本例配置的同步任务 |
| 0.35 ms | MCU 完成并发布一份新反馈到 ESC |
| 1.00 ms | 下一条 LRW 到达，可读取这份新反馈 |

在这个具体安排中，0.35 ms 发布的反馈由下一轮 LRW 读走。如果同一周期 0.50 ms 还安排了一条 LRD，它就有机会提前读走；如果新反馈直到 1.00 ms 的读访问之后才发布，则该次读访问仍只能取得此前的完整版本。

所以，EtherCAT 不统一规定“本轮发送目标，下一轮必定返回这个目标对应的反馈”。尤其实际位置只是采样时电机的位置，不表示电机已经运动到本轮目标。MCU 处理、PWM 生效和机械运动分别有自己的耗时。

运行期间，
主站继续检查 WKC、AL 状态和必要的 DC 误差，
从站通过[看门狗](../../诊断与调试/看门狗/看门狗.md)及应用机制处理超时或故障。
