# 主站配置

主站既要决定设备怎样协同工作，也要实际执行通信。可以把这两项职责分成配置与运行，但它们不一定是两个完全独立的软件，也不必全部离线完成。

## 配置工具与运行时

配置工具负责建立设备和数据关系，例如选择从站型号、排列拓扑、选择 PDO、确定周期与同步模式。TwinCAT 提供工程配置和运行环境。

主站运行时负责实际发现、初始化和访问从站，按周期准备输出、收回输入，并检查 WKC、状态和异常。SOEM 是主站软件库的一个例子。具体实时性取决于操作系统、网卡驱动和任务调度，不能认为有了协议栈就自动获得确定的通信周期。

## 离线建立与在线扫描

离线建立工程时，工具根据导入的 [ESI](../设备描述/设备描述.md) 选择设备，并按预期接线配置拓扑。

在线扫描时，主站从实际网络读取从站数量、位置、端口状态和 SII 身份，再与工程预期及设备描述匹配。配置站地址尚未建立时，可以使用[自动增量寻址](../../通信机制/寻址与命令/寻址与命令.md)逐站访问。

扫描得到的不只是“有几台”，还包括它们以什么次序和分支关系相连。设备型号、修订、端口路径或数量与工程不一致，都可能影响后续数据布局和同步配置。

## 配置时需要确定的关系

| 配置项 | 要确定什么 |
| --- | --- |
| 总线周期 | 每隔多久交换数据，是否满足设备与控制任务要求 |
| PDO 布局 | 每站交换哪些对象、顺序、长度和方向 |
| 过程映像 | 主站如何组织各设备的输入和输出数据 |
| SM | 各缓冲区在 ESC 中的位置、大小、方向和模式 |
| FMMU | 逻辑过程映像怎样对应各站内部地址 |
| DC 与 SYNC | 使用何种同步模式、周期、启动时刻及相位 |

这些内容相互依赖。例如改变 PDO 长度，会影响 SM 长度、FMMU 映射和主站过程映像的偏移。

周期数据可以安排在一个或多个 Datagram、一个或多个 Ethernet 帧中，不要求把所有设备永远塞进同一帧。如何拆分取决于数据量、访问方式和主站调度。

## 配置要通过从站验收

主站写完配置后，需要请求相应 [AL 状态迁移](../AL状态机/AL状态机.md)，并读取状态确认。从站应用会检查邮箱、过程数据、同步和自身运行条件；不能只看主站已经发出配置写命令，就认为配置生效且可以运行。

完整的依赖关系见[启动与周期运行](../启动与周期运行/启动与周期运行.md)。
