# EEPROM 访问

[SII 与 ESI](../SII与ESI/SII与ESI.md)说明保存了什么信息。本页说明主站或 MCU 怎样通过 ESC 的命令接口访问 EEPROM。以 ET1100 外部 I²C EEPROM 为例，网线上传输的是 ESC 寄存器访问，I²C 波形由 ESC 的 EEPROM 控制器产生。

## 先取得访问控制权

| 寄存器位 | 作用 |
| --- | --- |
| `0x0500.bit0` | 主站将 EEPROM 控制分配给 PDI |
| `0x0500.bit1` | 强制清除 `0x0501.bit0`，用于收回 PDI 占用 |
| `0x0501.bit0` | PDI 占用/释放 EEPROM 接口的状态 |

默认由 EtherCAT 侧控制。分配位与占用位都影响访问归属；只把 `0x0500` 写0，不能忽略 PDI 原有占用状态。PDI 设置占用还须满足该芯片的分配和强制访问条件。

这些位管理命令接口所有权，不是要写入 EEPROM 的数据，也不代表 MCU 直接接管了 EEPROM 的 I²C 引脚。

## 命令、地址与数据

| ESC 地址 | 长度 | 作用 |
| --- | --- | --- |
| `0x0502～0x0503` | 2 B | EEPROM Control/Status |
| `0x0504～0x0507` | 4 B | EEPROM 字地址，每单位2 B |
| `0x0508` 起 | 4或8 B读结果 | EEPROM Data；写命令使用低2 B |

例如 EEPROM 地址 `0x000C` 表示 EEPROM 字节偏移 `0x0018`，与 ESC 内部地址 `0x000C` 完全不同。

Control/Status 位号按从 `0x0502` 开始的 **16位值**编号：

| 位 | 含义 |
| --- | --- |
| bit0 | ECAT Write Enable；PDI拥有控制时按芯片定义为1 |
| bit6 | 0：每次读返回4 B；1：每次读返回8 B；ET1100为1 |
| bit10:8 | `000` 空闲/清相关错误；`001` 读；`010` 写；`100` Reload |
| bit11 | ESC启动配置区校验错误 |
| bit12 | EEPROM尚未成功加载，可能仍在加载或已失败 |
| bit13 | EEPROM未应答或命令无效，须结合刚才的操作判断 |
| bit14 | 发出写命令时未开启写使能 |
| bit15 | Busy：接口正在处理操作 |

“一次能读8 B”不等于“一次能写8 B”。ET1100 的正常 EEPROM Write 使用一个16位字。

## 一次读取的顺序

1. 确认控制权允许，且 Busy=0。
2. 设置 EEPROM 字地址，并发出 Read 命令。
3. 轮询 Busy；Busy=1时，数据区可能仍为旧值，不应作为新结果。
4. Busy=0后检查错误位，再取 `0x0508` 起的有效结果。
5. 需要继续读取时按本芯片返回长度推进字地址，再发下一次命令。

笔记中的 `80 01 0C 00` 从 `0x0502` 写入4 B，分为控制值 `0x0180` 和地址低16位 `0x000C`，不是“读取4 B”的长度字段。必须同时知道地址高位的已有值。该例返回状态 `0x0080` 的 bit6=0，表示4 B读取能力，不能当成 ET1100 的8 B实现。

## 写入、Reload 与完成判断

写入先设置地址和低2 B数据，再在有效访问窗口内设置 Write Enable 并发写命令。ECAT 写使能在下一帧 SOF 自清零，不能在很早的一帧中使能、隔若干帧才发写命令。完成后仍须等待 Busy 并检查错误。

EEPROM内部写入可能耗时数毫秒，不能按普通 RAM 的速度连续写而不检查状态。Reload 要求 ESC 重新加载规定的配置内容，与修改运行时 PDO 不是同一操作；部分字段仅在首次上电加载时采用，不能假定 Reload 重置整个 ESC。

Busy 反映命令是否结束，AL 状态则反映通信运行阶段；两者不能替代。状态迁移见[AL 状态机](../../AL状态机/AL状态机.md)。
